# BTC Backtest + MiroFish Scenario Log PoC — 要件定義書

作成日: 2026-05-11

## 1. PoC概要

### 目的

BTCの過去価格データを使い、単純な売買ルールのバックテストを実施し、各判断の根拠とMiroFishによる補助的なリスクシナリオを保存・表示できるか検証する。将来の実売買API連携を想定した「検証・学習用」の基盤構築。

### PoCの位置づけ

- **Phase 0**: 調査・PoC方針決定 → **本ドキュメント**
- **Phase 1**: データ取得とバックテスト → 次フェーズ
- **Phase 2**: ペーパートレード
- **Phase 3以降**: 手動承認付き売買、上限付き自動売買

本PoCはPhase 0～Phase 1の完了を目指し、実売買には進まない。

## 2. 対象範囲

### 対象

| 項目 | 内容 |
|---|---|
| **対象銘柄** | BTC/USDT または BTC/USD |
| **価格データ** | 日足 (daily) または 4時間足 (4h) |
| **データ期間** | 過去6ヶ月～2年程度 |
| **実行形態** | バックテストのみ |
| **資金** | 仮想資金（初期10,000 USDTなど） |
| **実売買** | 実施しない |
| **APIキー** | 不要（公開データのみ） |

### 対象外

- 実売買注文
- ユーザー資金管理
- レバレッジ・先物・オプション
- 複数銘柄ポートフォリオ
- 最適化エンジン
- 利益予測・推奨銘柄表示
- 自動売買機能
- 高頻度取引

## 3. 使用する価格データ

### データソース

**優先度1**: Binance Spot API `/api/v3/klines`
- 理由：無料、公開API、OHLCVが取得しやすい
- 欠点：地域制限、規約変更リスク

**優先度2**: CCXT経由での複数取引所（Coinbase、Kraken等）
- 理由：統一インターフェース、将来複数取引所対応

**優先度3**: ローカルCSV/Parquetファイル
- 理由：API障害時の回避、デバッグ用

### データ品質要件

- OHLCVすべてが存在（NaNなし）
- タイムスタンプが昇順、重複なし
- 取得元、取得日時、データ版を記録
- 欠損検出時は処理を中止し、ログに出力

## 4. 売買ロジック（初期版）

### 戦略：SMA ゴールデンクロス / デッドクロス

| パラメータ | 値 |
|---|---|
| 短期SMA期間 | 9日 |
| 長期SMA期間 | 21日 |
| 手数料 | 0.1% (取引所平均) |
| スリッページ | 0.05% |
| ポジションサイズ | 固定（全資金の90%） |

### 売買判断ルール

| 条件 | 判定 | 説明 |
|---|---|---|
| SMA9 > SMA21（ゴールデンクロス） | **BUY** | 上昇トレンド入場 |
| SMA9 < SMA21（デッドクロス） | **SELL** | 下降トレンド離脱 |
| ポジション保有中 | **HOLD** | 信号が反転するまで保持 |
| リスク停止条件（将来拡張） | **RISK_STOP** | 最大ドローダウン超過時など |
